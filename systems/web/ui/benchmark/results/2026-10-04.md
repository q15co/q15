# Streaming measurements: 2026-10-04

The 1,000-message workload uses 94.6% less main-thread task time and 99.0% less script time. Its p95
frame-to-rendered-text latency falls from 1,296ms to 171ms. The independent large-answer workload
uses 61.9% less main-thread task time, with a latency tradeoff: p95 increases from 312ms to 357ms.
The 40ms Markdown window reduces repeated parsing while keeping terminal rendering immediate. Large
full-document Markdown parsing still produces long tasks.

## Workloads and results

The history workloads contain 100 or 1,000 completed assistant messages, each with reasoning, tool
input/output and GFM text. Both receive the same 24 text/reasoning pairs, with a replacement
snapshot every tenth pair and one tool call/result. The active answer ends at 4,352 UTF-8 bytes. The
independent large-answer workload starts with no history, receives 120 pairs, and ends at 81,430
bytes. It crosses incomplete fences, nested lists, tables and references. Every workload ends with
the full final source.

All values below are **base → implementation**, in milliseconds except task counts. Task/script
times and long-task counts/durations are means across two runs. Latency median/p95 use the pooled
marker samples and nearest-rank quantiles. A long task exceeds 50ms. Latency measures the first
animation frame observing rendered answer text; it measures a paint opportunity, not display or
compositor latency. Hidden reasoning does not count as visible answer text.

Fixing only the working label's font axes retains the other normal-motion animations. In the
implementation runs, this lowers layout from 189ms to 60ms and total task time from 1,849ms to
1,756ms. This control suggests font-axis animation contributes layout work, while historical
reparsing accounts for the much larger baseline script cost. Remaining browser work still grows with
the rendered DOM; the deterministic counts below establish that live updates no longer scan or
rerender completed history.

The large-answer latency increase is explicit: median grows by 31ms and p95 by 45ms with normal
motion; reduced-motion p95 grows by 26ms. Coalescing gives the browser more gaps between expensive
full-document parses. Each individual parse remains costly. Final HTML is compared against
unthrottled canonical Markdown in the component test. No socket/codec improvement is attributed to
this change; #209 remains separate.

## Deterministic checks and validation

After initial loading, the same 20 text/reasoning pairs at a simulated 16ms cadence produce:

| Counter                                             | 100 messages | 1,000 messages |
| --------------------------------------------------- | -----------: | -------------: |
| Historical row renders                              |            0 |              0 |
| Historical grouping visits during deltas/snapshots  |            0 |              0 |
| Unchanged tool argument/pretty parses               |            0 |              0 |
| Active Markdown parses, text and reasoning combined |           12 |             12 |

The reducer test rejects every historical-array property access for deltas and snapshots of model
start, text, reasoning, tool calls and results. Historical row renders also remain zero at turn
startup and completion. Separate tests cover large growing Markdown, timer cancellation, immediate
terminal flush, scrolling/paging/deep links, and disclosures through completion/resync.

Passed: `make project-setup`, changed-file `make fmt` / `make lint-changed`, `make ui-lint`,
`make ui-test-coverage` (170 tests; 98.06% statements, 94.63% branches, 99.1% functions, 99.36%
